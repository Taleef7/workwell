## 1. What changed (Nicole's corrections, 2026-07-24)

1. **For official CMS eCQMs: download and RUN the official published CQL — don't reauthor it.**
   ("If the CQL exists, use it… other than maybe as an educational exercise.")
2. **The real EHR proof path is QRDA-I ingest → calculate → regenerate QRDA-I + QRDA-III → Cypress →
   ONC proctored certification.** MADiE is measure-*authoring* tooling — not how an EHR verifies its
   calculations. MIE is ONC-certified on ~33 of 49 eCQMs; re-tests roughly every two years.
3. **Priority measures: CMS2, CMS68, CMS122, CMS125, CMS130, CMS138, CMS165, CMS951** — MIE's most
   commonly used set (dropped in chat).
4. **Self-authored CQL is the value exactly where no official definition exists**: occupational
   health/OSHA (no published CQL anywhere) and HEDIS-insight (commercial-payer measures are black-box,
   spec'd behind NCQA paywalls — interpretable CQL gives providers visibility they can't otherwise get).
   MIE could become the **community steward of occupational measures** (NCQA acceptance is an open
   process; a long road, deliberately walkable).
5. **DEQM/quality-on-FHIR is the direction, not the present.** CMS/QPP has no FHIR submission endpoints
   yet (~2030 horizon); today reporting is literal QRDA file movement. The eCQI transition diagram's
   invariant: **CQL survives both columns** (QDM→QI-Core; HQMF→QM IG; QRDA-I/III→DEQM
   Individual/Summary = MeasureReport).

Also: the HL7 CQI Work Group meets **Fridays** (Nicole attends; Doug wants Taleef attending + reporting
back). eCQMs for year N+1 publish each May; clinics focus on prior-year data Jan–Mar.

## 3. North star (end state)

**WorkWell = an open-source, modular clinical-quality engine + studio that:**
1. **Runs official eCQMs verbatim** (published MADiE/eCQI QICore artifacts, hash-pinned, VSAC-pinned)
   over any data source — FHIR API (WebChart/teatea), WCDB SQL (shim), plain JSON bundles — proven by
   the certification-shaped loop (QRDA-I in → calculate → QRDA-I/III out → Cypress/CVU+ green).
2. **Authors, tests, and verifies the measures that don't officially exist** — occupational/OSHA and
   payer-insight (HEDIS-style) — with rule→CQL→SQL codegen, self-authored MADiE-style test cases
   published in the community `dqm-content` shape, and an NCQA stewardship trajectory.
3. **Ships as publishable packages** (`@workwell/*`, pitched for `@mieweb/*` adoption) other MIE
   products and the community can `npm i` — documented, semver'd, CI-published.
4. **Stays on the standards curve**: QI-Core stamped; MeasureReport = the DEQM resource; CQI WG
   participation; ready when CMS/QPP opens FHIR endpoints.

**Two-track posture (deliberate, owner-confirmed):** execution + data model live on the dQM/FHIR
column (QI-Core STU7 = US Core 7 = exactly WebChart's verified FHIR surface; QI-Core's QDM→QI-Core
mapping guarantee is the formal basis); reporting stays on the current QRDA column until CMS/QPP
moves. QDM appears ONLY as a translation at the QRDA export/import boundary — never a QDM-native
engine. MADiE cases are PERMANENT CI regression gates (the engineering floor: "we calculate what the
measure developer intended"), distinct from the QRDA/CVU+ proof (M-B: "we behave like an EHR proving
it") — both kept forever.

## 5. Key audit facts (verified 2026-07-24)

- **Engine extractability:** `src/engine/` had exactly 4 app-layer couplings — `engine-factory.ts`'s
  `getStores` value import (app wiring), two type-only imports of the 30-method `ValueSetStore` (engine
  used only `listAll()`), and `evaluate-measure.ts`'s `@mieweb/cloud` import (served only
  `UnconfiguredEngine`). Severed → the tree reaches nothing outside itself; the **eval core**'s deps are
  `cql-execution` + `cql-exec-fhir` only and it is node:fs-free/Workers-portable;
  `evaluate(input.elm, input.metaOverride)` already supports consumer-supplied measures.
  **(Severance shipped as extraction PR-1, 2026-07-24.)** Two items of **extraction debt remain in the
  tree** and are PR-2's job, not PR-1's — they are why the package manifest is not yet a two-dep file:
  `@cqframework/cql/cql-to-elm` in `cql/cql-translator.ts` (the ELM Explorer, reached from
  `routes/measures.ts`; §7.1 keeps it in the app) and `node:fs`/`node:path`/`node:url` in the four
  `*-cli.ts` entrypoints. Both are pinned by the boundary test's allowlist, so neither can spread.
- **Official-path machinery exists** (literal-diff + official-cases over fqm-execution, 121/121 MADiE
  green) but is CMS122-hardcoded, vendored at stale v0.5.000 (CMS125 not vendored), and ADR-026-fenced
  diagnostic-only. `MeasureExecutor` seam is clean but env-global; official-first needs per-measure
  routing. MeasureReport D1/D2 were already fixed (PR #294/ADR-031) — PR-3 below only generalizes.
- **QRDA-I does not exist anywhere**; QRDA-III is a stub. Cypress + CVU+ are open source
  (github.com/projectcypress/cypress), Docker-runnable; projecttacoma/cqm-reports (Ruby) is the QRDA-I
  reference implementation (spec reference only, not a dependency).
- **All 8 priority measures have official QICore v1.0.000 artifacts + MADiE test cases** in
  `cqframework/dqm-content-qicore-2025` (CMS2FHIRPCSDepScreenAndFollowUp, CMS68FHIRDocumentationCurrentMeds,
  CMS122FHIRDiabetesAssessGT9Pct, CMS125FHIRBreastCancerScreen, CMS130FHIRColorectalCancerScrn,
  CMS138FHIRTobaccoScrnCessation, CMS165FHIRControllingHighBP, CMS951FHIRKidneyHealthEval — "Kidney
  Health Evaluation", MIPS 488). 6 of 8 are Draft catalog stubs today.
- **WebChart data gaps for the 6 new measures:** shim serves Patient/Observation/Procedure only
  (Condition/Encounter advertised but empty; no medications path). Closest: CMS165 + CMS951 (labs
  present, need Condition). CMS68/138 blocked on a medications path. The PR #316 AI-YAML ingest loop is
  the tool to seed missing data types into dev-wcdb.
- **Honesty nuance:** what ONC certifies *today* is the QDM/QRDA form; the QICore artifacts are the
  official dQM (future-column) form of the same measures, validated against MADiE expecteds. WorkWell
  is not an EHR seeking ONC certification — running the official FHIR artifacts is both the right
  engineering choice (we're FHIR-native) and the direction-of-travel choice. Say it exactly that way.

## 7. Target architecture (approved design)

### 7.1 Package layout
```
backend-ts/
  pnpm-workspace.yaml        # packages: [".", "packages/*", "../external/mieweb-cloud/packages/*"]
  package.json               # @workwell/api-ts — the APP stays at "."
  src/                       # app: routes, run pipeline, stores, wiring/, standards lab, synthetic
  measures/                  # authored YAML+CQL (codegen inputs), + official/ vendored bundles
  packages/
    measure-engine/          # @workwell/measure-engine    — deps: cql-execution + cql-exec-fhir ONLY
    official-executor/       # @workwell/official-executor — deps: fqm-execution 1.8.5 (the quarantine)
    qrda/                    # @workwell/qrda              — M-B (cat1/, cat3/, CVU+ scripts)
    measure-codegen/         # Wave 2
    measure-content/         # Wave 2, only if the MIE pitch demands
```
- `cql-translator.ts` (ELM Explorer) stays in the app — preserves the 2-dep engine story.
- fqm-isolation test evolves into 3 boundary tests: (1) fqm-execution in deps of ONLY
  official-executor's package.json + zero direct imports in app src; (2) `@workwell/official-executor`
  importable only from `src/wiring/executor-router.ts`, `src/standards/*`, the official-cases CLI;
  (3) importing the package entry loads no fqm into the module graph (lazy `await import` discipline).
- **Boundary-test discipline (learned in PR-1 review, applies to all of the above):** a source-grepping
  arch guard must extract EVERY module-specifier form — static `from`, side-effect `import "x"`, dynamic
  `import("x")`, `require("x")`, `export … from "x"` — not two hand-picked shapes, and the matcher itself
  must be unit-tested against each form plus clean controls. A guard that silently passes while the
  dependency returns is worse than no guard. `engine/engine-boundary.test.ts` is the reference
  implementation.

### 7.2 Per-measure executor routing
`src/wiring/executor-router.ts`: `routedEngineForEnv(env)` returns a `RoutedEngine extends
EvaluateMeasureBinding` dispatching on `input.measureId` — no downstream signature changes.
- **`WORKWELL_OFFICIAL_MEASURES="cms122,cms125"`** — explicit comma-list, never "all"; boot-loud
  validation (listed id must exist in catalog AND have a vendored manifest, else throw).
- Unset = wraps `engineForEnv`, byte-identical (parity test).
- Measure→artifact association generated from `measures/official/*/manifest.json` — never in the
  engine's measure-registry.
- No inline shadow execution: the shadow period reuses the standards-lab diff machinery post-run.

### 7.3 Official executor contract
- **Bundle convention:** `measures/official/<catalogId>/{bundle.json, manifest.json,
  supplemental-expansions.json?, test-cases/}`; version in the manifest (`catalogId, ecqmId, version,
  sourceUrl, sha256, scoring, improvementNotation, numeratorMeansCompliant, knownBadCases[]`).
  Vendor-time minification (strip non-elm+json Library.content + narratives, ~50%).
- **Memory:** prepared-context LRU(3) + measure-major run iteration (each context built once per run).
- **Terminology:** bundle-shipped expansions PRIMARY (what the 121/121 validation exercised);
  1000-code truncations re-expanded from imported VSAC rows at VENDOR time into
  supplemental-expansions.json; unpatchable → the vendor script fails. Runtime never mixes authorities.
- **Vocabulary: the 5-bucket `OutcomeStatus` enum does NOT extend.** Regulatory population truth
  persists losslessly in `evidence_json.official.populationResults` (QRDA/MeasureReport read THAT).
  Mapping via `manifest.numeratorMeansCompliant`; DENEXCEP→EXCLUDED + populationResults marker
  (unblocks CMS68 with zero enum change). Accepted trade-off: official-routed measures never emit
  DUE_SOON (documented in the ADR; forecaster stays a descriptive overlay).
- **evidence_json (additive):** `expressionResults` from fqm statementResults + `official: {ecqmId,
  version, engine, populationResults}`.
- **logic_version (#263):** `sha256("official-fqm:" + version + ":" + bundleSha)` — re-vendor
  invalidates incremental reuse; authored→official flip forces full re-eval.
- **ADR "Official-first execution"** supersedes ADR-026's diagnostic-only framing: the real invariant
  ("heavy deps off the cold-start/request path + CQL sole outcome authority") survives — package
  boundary + lazy import; official artifacts ARE CQL, so ADR-008 is upheld.

     — the AUTHORED ELM. A measure flipped to official execution therefore keeps the *same*
     `logic_version`, so the `eval_state` cache would copy AUTHORED outcomes forward for a measure now
     running the official artifact, and a re-vendor of that artifact would not invalidate them either.

     `IncrementalDeps`.

     data legitimately retrieves nothing), so it belongs with the batching: if no retrieve matched

     complete, and should fail loudly instead. The per-subject half now ships on

## 8. Risks

| Risk | Mitigation |
|---|---|
| fqm deps in the worker request path (ADR-026 concern) | package quarantine + lazy import + per-measure routing; supersede ADR-026 explicitly; benchmark before flip |
| 8 bundles × 9–17 MB (image size + memory; the 300s deploy-window lesson) | vendor-time minification; LRU(3); `.dockerignore` test-cases; watch image size in CI |
| VSAC/CPT expansion redistribution licensing in PUBLIC packages | legal check before C3; public = fetch-at-build, private app may vendor |
| DENEXCEP/NUMEX vocabulary blast radius | non-breaking mapping + populationResults; extend enum only with evidence it's lossy |
| QRDA-I is QDM-shaped, we're FHIR-native | CVU+ iterative validation; B3 import builds the QDM↔FHIR mapping both ways |
| Official-path perf vs 68 ms/eval | benchmark at A2; incremental-eval logic_version covers official bundles |
| Nicole-cadence scope creep | milestone WIP limits; new asks → issues, triaged at checkpoints |
| Demo-stack stability during flips | shadow mode + inert-unless-configured flag; flip = config change with rollback |
| Windows/OneDrive long paths for vendored content | vendor script flattens; short filenames; `core.longpaths` in CI docs |
